# Внедрение нового фронта (хендофф `handoff_3_экрана/`) — план

Источник: `frontend/handoff_3_экрана/` — 4 прототипа (`*.dc.html`, интерактивные мокапы на
внутреннем dc-рантайме, не React-код) + 3 спеки для разработчика (`*.md`, "... — внедрение").
Экраны: Мессенджер, База знаний (+ полноэкранная читалка документа), Проекты, Админ-панель.

## Гэп-анализ (на момент 2026-07-16)

Уже готово / почти совпадает с хендоффом:
- `AppRail.jsx` — узкий рейл 62px уже переключает `chats`/`knowledge`/`projects`, структура совпадает с `НАВИГАЦИЯ - внедрение.md`.
- Тема — CSS-переменные почти все совпадают по именам (`--bg`, `--sidebar`, `--surface`, `--accent`, `--accent-soft`, `--hover`, `--ok`...). Не хватает `--rail`. Ключ в localStorage свой (`theme`, не `msgr-theme` из прототипа) — менять не нужно, это внутреннее имя прототипа.
- `ProjectsPage.jsx` — уже реализован близко к `Проекты.dc.html` (участники, задачи, файлы, активность, связанные документы). Нужна только сверка деталей, не переписывание.

Нужно строить с нуля:
- **Полноэкранная читалка документа** (`ЧИТАЛКА ДОКУМЕНТА - внедрение.md`) — сейчас в `KnowledgeBasePage.jsx` только боковая шторка.
- **Админ-панель** (`АДМИН-ПАНЕЛЬ - внедрение.md`) — не существует во `frontend` вообще.

## Решения, принятые в обсуждении

- Админ-панель — **новый раздел внутри `frontend`** (не в отдельном уже существующем `admin-panel/` приложении). Гейтинг по роли — на бэкенде, фронт только скрывает.
- Подход к работе: **сначала фронт, API под него подстраиваем/дописываем позже**. Для данных, которых бэкенд пока не отдаёт (текст главы, таблицы главы, всё для админки — статусы сервисов/Celery/пользователи), фронт строится против явного контракта, но данные — заглушки/моки до отдельного шага с бэкендом.

## Порядок внедрения

### 1. Читалка документа (начинаем с неё — продолжает уже сделанный бэкенд: `document_chapters`/`document_tables`, `GET /documents/{doc_id}`)
- Новый компонент `DocumentReader.jsx` (fixed, full-screen) вместо шторки в `KnowledgeBasePage.jsx`.
- Состояние `chapterIdx`/`contentMode` ('summary'|'full').
- Оглавление — по реальным главам (`chapters[].title` уже приходит с бэкенда).
- Текст главы и таблицы — контракт на будущее: `GET /documents/{doc_id}/chapters/{n}` → `{ text, tables }`. Бэкенда пока нет (текст лежит в S3 по `s3_md_path`, но эндпоинта отдать его нет) — на фронте пока моковые данные.
- Блок «Векторизация» (`chunk_size`/`overlap`/`model`/`dim`/`metric`) — уже решено, что это заглушки `—`/`null` (см. текущую интеграцию `stub_routes.py`).
- Верификация: открывается на весь экран по клику на карточку, оглавление реальное, переключение «Обзор/глава» и «Краткое/Весь текст» работает.

### 2. Админ-панель
- Новая страница `AdminPage.jsx` + хук `useAdmin.js` (по образцу `useProjects.js`/`useKnowledgeBase.js`).
- 4 вкладки — отдельные под-компоненты: `SystemStatusTab`, `DocumentsTab` (shared/personal + user-picker с поиском, НЕ чипы), `UsersTab`, `StatsTab`.
- **Перед кодом проверить**: откуда на фронте брать роль пользователя (есть ли она уже в `useAuth`/текущем пользователе) — не проверяли.
- Все данные (`ServiceStatus`, `QdrantStats`, `CeleryTask`, `AdminUser`, `AdminDoc` с `scope: shared|personal`) — моки, реального бэкенда под это нет.
- Верификация: раздел виден только у admin-роли, все 4 вкладки рендерятся на моках.

### 3. Рейл — мелкая доводка
- Условный рендер 4-й (admin) иконки в `AppRail.jsx` по роли.
- Добавить `--rail` в CSS-токены обеих тем (проверить сначала, не хватает ли реально отдельной переменной от `--sidebar`, или рейл и так использует `--sidebar` без проблем).

### 4. Проекты — сверка с прототипом
- Не переписывание — только список расхождений с `Проекты.dc.html`, если найдутся, отдельным маленьким шагом.
