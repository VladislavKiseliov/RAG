## 🔴 Баги

| # | Было | Файл | Строка |
|---|---|---|---|
| B1 | JWT access-токен передаётся в query-параметре WebSocket URL (`?token=...`). У nginx нет кастомного `log_format` для `/websocket/` (и вообще нигде), поэтому дефолтный `combined`-формат пишет `$request` целиком, включая query string, — токен уходит в access-логи nginx в открытом виде на каждое WS-подключение. Любой с доступом на чтение к логам/пайплайну доставки логов может скопировать токен и открыть WS-сессию (или вызвать `/api/*`, если это тот же JWT) от имени пользователя до истечения токена. Токен в URL также оседает в истории браузера и логах промежуточных прокси/CDN | `src/config/api.jsx` | 18–21 |

## 🟠 Архитектурные / поведенческие проблемы

| # | Описание | Файл | Строка |
|---|---|---|---|
| A1 | Access/refresh токены в `localStorage`, читаемы любым JS на странице. Активной XSS сегодня не найдено (см. шапку файла), но это классический компромисс: в момент, когда кто-то добавит `rehype-raw` (например, для рендера HTML-таблиц из Docling) или markdown-зависимость с обходом — оба токена становятся эксфильтрируемыми без httpOnly-cookie фолбэка | `hooks/useAuth.js`, `pages/AuthPage.jsx` | 34–35, 59–60 |
| A2 | Гейтинг админки — только в React-дереве (`section === 'admin' && isAdmin`); подтверждено, что backend отдельно и правильно enforce'ит admin-роль на самих `/admin/*` эндпоинтах (`admin_routes.py` + `dependencies.py`) — то есть это defense-in-depth, не реальная дыра. Зафиксировано, чтобы не приняли по ошибке за настоящий контроль доступа | `pages/ChatPage.jsx`, `hooks/useCurrentUser.js` | 247, 24 |
| A3 | Сырые строки `detail` от backend показываются пользователю без общего fallback на неожиданный формат ответа. Ошибки валидации Pydantic (массивы) обрабатываются, но любой эндпоинт, вернувший неструктурированную/внутреннюю строку в `detail` (фрагмент стека, ошибку SQL), будет показан пользователю как есть | `api/client.js`, `pages/AuthPage.jsx` | 20–21, 43–44, 43–47, 66 |
| A4 | Ограничение типа файла при загрузке документа — только `accept=".pdf,.md,.docx,.txt,.markdown"` на `<input type="file">`, тривиально обходится (drag-and-drop, переименование, скриптовый запрос). Не проверено, перевалидирует ли тип backend/Docling-пайплайн заново — сверить с реальным поведением backend, не полагаться на предположение | `components/admin/DocumentsTab.jsx` | 89 |
| A5 | Загрузка стороннего шрифта — `@import` Google Fonts (`https://fonts.googleapis.com`) на каждой загрузке страницы, утечка IP/UA клиента в Google. Не про токены/данные пользователей — приватность/полнота self-hosted решения | `src/styles/main.css` | 10 |

## ✅ Проверено аудитом, проблем не найдено

Гонка обновления токена (`useAuth.js:70-83`) корректно дедуплицирована через синхронный `useRef`-промис-гвард. WS-reconnect (`useMessengerSocket.js`) закрывает старый сокет перед переподключением, каждый раз берёт свежий токен, backoff капается на 30с — дублей/утечки состояния сессии не найдено. Нет `console.log` токенов/пользовательских данных нигде в `src/`. Нет open-redirect поверхности — никакой код не читает `redirect`/`next`/`returnUrl` и не пишет `window.location.href =` из request-контролируемого ввода.
