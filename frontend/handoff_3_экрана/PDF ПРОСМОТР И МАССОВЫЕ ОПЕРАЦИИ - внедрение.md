# Просмотр PDF + массовые операции с документами — внедрение

Дополняет **База знаний.dc.html** и **Админ-панель.dc.html**.

---

## 1. База знаний — просмотр исходного файла на странице

Кнопка «⤢ Открыть исходник» в шапке ридера документа открывает модалку с `<iframe src="{{ dFileUrl }}">`
поверх страницы (не новую вкладку) + ссылка «Открыть в новой вкладке» рядом, на случай печати/скачивания.

### Что нужно с бэкенда
```ts
type Document = {
  // ...существующие поля
  fileUrl: string;   // прямая ссылка на PDF/файл (presigned S3/MinIO URL или /files/{id})
};
```
`fileUrl` должен отдавать `Content-Type` и заголовки, разрешающие встраивание в `<iframe>`
(без `X-Frame-Options: DENY` и с корректным `Content-Disposition: inline`, не `attachment`).
Для не-PDF форматов (DOCX и т.п.) — либо конвертировать в PDF на сервере для превью, либо
показывать сообщение "предпросмотр недоступен для этого формата" и оставлять только внешнюю ссылку.

### Состояние/логика (уже в компоненте)
```js
sourceViewerOpen: boolean
openSource() / closeSource()
```

## 2. Админ-панель — массовые операции с документами

Кнопка **«☑ Выбрать…»** над таблицей документов открывает модальное окно:

1. **Действия** (чекбоксы, можно оба сразу): «↻ Переиндексировать» и «✦ Сформировать краткое по главам».
2. **Список документов** с чекбоксами — прокручиваемый (`overflow-y:auto`), не тянет за собой шапку/футер.
3. **Поиск** по названию/владельцу — фильтрует список вживую, работает при 100–200+ документах.
4. **«Выбрать/Снять видимые»** — действует только на текущий отфильтрованный набор, а не на все документы разом.
5. Счётчик «N выбрано» и кнопка «Запустить».

Таблица документов дополнена двумя колонками статуса: **«В индексе»** и **«Саммари»** (✓/–),
чтобы сразу видеть, каким документам действие ещё нужно.

### Модель данных
```ts
type AdminDoc = {
  // ...существующие поля
  state: 'indexed' | 'processing';   // -> колонка "В индексе"
  hasSummary: boolean;               // -> колонка "Саммари"
};
```

### Реальные операции (вместо мока в прототипе)
```
POST /admin/documents/bulk-reindex     { ids: string[] }
POST /admin/documents/bulk-summarize   { ids: string[] }   // краткое по главам через LLM
```
На фронте — после отправки опрашивать статус (polling) или слушать WebSocket/SSE, обновляя
`state`/`hasSummary` по мере завершения задач в Celery, а не только оптимистично через таймаут,
как в прототипе.

### Ограничение на масштаб
Для сотен документов список в модалке стоит подгружать постранично / с серверным поиском
(`GET /admin/documents?search=...&scope=...`), а не держать весь список в памяти клиента —
в прототипе фильтрация клиентская, для реальных объёмов перенести поиск на бэкенд.
