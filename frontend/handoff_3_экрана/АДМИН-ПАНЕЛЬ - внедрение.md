# Админ-панель — пакет для внедрения

Экран только для роли admin (гейтинг — на бэкенде). 4 вкладки: статус системы, документы
(общие/личные), пользователи, статистика.

---

## 1. Данные, которые нужны с бэкенда

```ts
type ServiceStatus = { name:string; port:number; status:'online'|'degraded'|'offline'; latencyMs:number };

type QdrantStats = { collection:string; vectors:number; segments:number; sizeLabel:string; optimizerOnline:boolean };

type CeleryTask = { id:string; name:string; subject:string; state:'running'|'queued'|'success'|'failed'; progress:number };

type AdminDoc = {
  id:string; title:string; owner:string; ownerId?:string;   // ownerId только для личных
  scope:'shared'|'personal'; chunks:number; points:number; size:string; state:'indexed'|'processing';
};

type AdminUser = { id:string; name:string; email:string; role:'Гость'|'Инженер'|'Админ'; docsCount:number; lastActiveLabel:string; active:boolean };
```

Опрашивать `ServiceStatus[]` поллингом (5–10 сек) или через health-check эндпоинт каждого сервиса.
Celery-задачи — через Celery events / Flower API / собственную таблицу задач с polling.

---

## 2. Состояние экрана

```js
tab: 'system' | 'docs' | 'users' | 'stats'
docScope: 'shared' | 'personal'          // только для вкладки "Документы"
personalUserId: string | null            // фильтр внутри "Личные базы"
userPickerOpen: boolean
userPickerQuery: string
docQuery: string
editingDocId: string | null
```

## 3. Вкладка «Статус системы»

- Сетка карточек 3×2: имя сервиса + порт, пилюля статуса (online зелёная / degraded жёлтая,
  пульсирующая точка / offline красная), задержка в ms.
- Карточка «Статистика Qdrant»: коллекция, число векторов, сегментов, размер, optimizer online/offline.
- Список задач Celery: точка-индикатор (пульсирует у running), имя таски, объект (какой документ/джоба),
  статус справа, прогресс-бар только у running.

```css
.status-pill        { display:inline-flex; align-items:center; gap:6px; padding:4px 10px; border-radius:7px; font-size:11.5px; font-weight:600; white-space:nowrap; }
.status-pill .dot    { width:6px; height:6px; border-radius:50%; }
.status-pill.online  { background:var(--ok-soft); color:var(--ok); }
.status-pill.degraded{ background:var(--warn-soft); color:var(--warn); }
.status-pill.offline { background:var(--bad-soft); color:var(--bad); }
@keyframes pulse { 0%,100% { opacity:1; } 50% { opacity:.4; } }
.status-pill.degraded .dot, .task-dot.running { animation: pulse 1.1s ease-in-out infinite; }
```

Поллинг: обновлять карточки на интервале (5–10 сек) и по кнопке «Обновить» (с крутящейся иконкой ↻,
`animation: spin .6s linear infinite` на время запроса).

## 4. Вкладка «Документы» — общие vs личные

Сегмент-переключатель наверху:

```html
<div class="segment">
  <button class="{{ scope==='shared' && 'active' }}" onClick="setScope('shared')">Общая база знаний</button>
  <button class="{{ scope==='personal' && 'active' }}" onClick="setScope('personal')">Личные базы пользователей</button>
</div>
```

Когда `scope==='personal'` — показывается **выпадающий список с поиском** для выбора пользователя
(важно: не чипы — при 100–200 пользователях чипы не масштабируются):

```html
<div class="user-picker">
  <button onClick="togglePicker">{{ selectedUser ? selectedUser.name + ' · ' + selectedUser.docsCount : 'Все пользователи · ' + totalPersonalDocs }} ▾</button>
  <div class="user-picker-panel" if="pickerOpen">
    <input placeholder="Найти пользователя…" value="{{ query }}" onInput="onSearch" />
    <div class="user-picker-list">                 <!-- max-height + overflow-y:auto -->
      <div onClick="selectUser(null)">Все пользователи</div>
      <div onClick="selectUser(u.id)" for="u in filteredUsers">
        <span class="avatar">{{ u.initials }}</span>{{ u.name }}<span class="count">{{ u.docsCount }}</span>
      </div>
    </div>
  </div>
</div>
```

Фильтрация списка — на клиенте по имени/email, если пользователей мало (< ~500); при большем объёме
дебаунсить и запрашивать `/admin/users?search=...` с сервера постранично.

Таблица документов (общая колоночная сетка что для shared, что для personal — только источник данных
разный): title (инлайн-редактирование по клику на ✎, Enter — сохранить, Esc — отмена), owner, chunks,
points, size, status-пилюля, кнопки ✎ / 🗑 (🗑 с подтверждением на реальном бэкенде — здесь удаляет сразу,
на проде добавьте confirm-диалог).

## 5. Вкладка «Пользователи»

Таблица: аватар-инициалы + имя, email, роль (клик по пилюле роли циклически переключает
Гость → Инженер → Админ — на проде замените на dropdown/модалку с подтверждением, циклический клик
только для прототипа), число документов, последняя активность, пилюля активен/заблокирован
(клик — toggle, на проде это должен быть отдельный запрос с подтверждением).

---

## 6. Вкладка «Статистика»

4 карточки-агрегата (документов, точек в БД, активных пользователей, задач в очереди) + список
топ-документов с барами по числу точек (`width: value/max*100%`).

---

## 7. Стили и токены

Тот же набор CSS-переменных, что в остальном приложении (`--bg`, `--card`, `--surface`, `--accent`,
`--muted`…) — полный список в `НАВИГАЦИЯ — внедрение.md`. Добавьте только:

```css
--warn: #d9a441;      --warn-soft: rgba(217,164,65,.15);   /* degraded */
--bad:  #d65f5f;       --bad-soft:  rgba(214,95,95,.14);    /* offline / заблокирован */
```

**Везде, где текст в одну строку соседствует с иконкой/точкой статуса — обязателен
`white-space: nowrap` и `flex-shrink:0` на точке.** Это была основная причина переносов текста
при верификации (вкладки, задержка "N ms", статус-лейблы, роль-пилюли).
