## 1. Проекты.dc.html — модель документооборота (бэкенда нет, см. Фичу 5 в `TODO.md`)

Новая модель: Проект → Раздел (шаблон по типу) → Подраздел (создаётся вручную, напр.
«Отопление»/«Вентиляция»/«Технология») → Документ (шифр + версии) → Пакет изменений (changeset).

### Экраны (view state в компоненте)
- **list** — список проектов, счётчики (всего/активны/на утверждении/отклонено).
- **overview** — обзор проекта, лента активности, ролевой виджет (см. ниже).
- **files** — дерево разделов/подразделов слева + таблица документов справа, поиск по шифру/названию.
- **document** — карточка документа: PDF-превью, история версий (с комментарием автора «что изменено»),
  заметки (пользовательские + AI), баннеры «отклонено»/«на утверждении».
- **queue** — очередь утверждения пакетов: превью файлов, предупреждение о конфликте версий,
  утвердить/отклонить (отклонение — с обязательным комментарием).
- **archive** — архив всех версий с фильтром по разделу.

### Демо-переключатель роли
Компактные кнопки «Р»/«И» внизу рейла (`setRoleManager`/`setRoleEngineer`) — переключает, что видно
(виджет очереди для руководителя vs список своих пакетов для инженера). **На проде — убрать**,
роль берётся из сессии пользователя.

### Подразделы
`project.subfolders[sectionId] = [{id, name}]`. Создаются через «+ Добавить подраздел» в дереве
(inline-инпут). Документ хранит `subfolderId` — на бэкенде это доп. колонка/таблица `subfolder`
с `parent_section_id`.

### Что нужно с бэкенда (сводно)
```ts
type Document = { id, code, name, sectionId, subfolderId?, projectId,
  approvedVersion: number|null, pendingChangesetId: string|null, lastRejectedChangesetId: string|null };
type DocVersion = { v, fileName, uploadedBy, approvedBy, date, comment };
type Changeset = { id, projectId, author, date, status:'pending'|'approved'|'rejected',
  comment, rejectionComment?, items: [{docId?, code, name, action:'new'|'replace', fromVersion?, toVersion?, fileName}] };
type Note = { id, author, text, isAI, date };
```
Конфликт версий (queue): при утверждении пакета сверить `fromVersion` пакета с текущим
`approvedVersion` документа — если разошлись, показать предупреждение (уже в UI, `conflict`/`conflictText`).

## 2. База знаний.dc.html

### 2.3 Таблица «Характеристики» в карточке документа (заменяет прежнюю «Векторизация»)
Новый набор полей вместо чанк-сайза/оверлапа/модели:
```
Объём — dPages стр.
Структура — dSectionCount глав
Чанков (фрагментов) — dChunks
Таблиц и схем — dTablesCount
Статус документа (во всю ширину) — dLifecycleStatus, напр. «Действует (Изм. от 01.06.2026)»
```
### Что нужно с бэкенда
```ts
type Document = {
  // ...существующие поля (title, size, pages, chunks, summary, sections[]...)
  fileUrl: string;          // прямая ссылка на исходный файл, iframe-embeddable
  tablesCount: number;      // кол-во таблиц/схем, извлечённых при парсинге
  lifecycleStatus: string;  // "Действует (Изм. от DD.MM.YYYY)" | "Черновик" | и т.п.
};
```
Старые поля `chunkSize/overlap/model/dim/metric` остаются в данных документа (используются на
других экранах/для админки), просто больше не выводятся в этой карточке.
