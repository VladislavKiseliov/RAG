# Заметки — пакет для внедрения

Отдельный раздел в левой панели (✎). Личные заметки пользователя: папки/теги,
закрепление, Markdown-редактор с превью, напоминания, и новый поток
«голос/поток мыслей → ИИ-черновик → редактирование → сохранение с индексацией».

---

## 1. Модель данных

```ts
type Tag = 'important' | 'idea' | 'todo' | 'question' | 'ref';   // расширяемый набор с цветом на тег

type Note = {
  id: string;
  title: string;
  folder: 'work' | 'ideas' | 'personal';
  tags: Tag[];
  pinned: boolean;
  reminder: string | null;     // ISO datetime, напр. "2026-07-21T10:00"
  followUp: boolean;            // флаг "на потом" без конкретного времени
  content: string;              // Markdown
  chunks: number; points: number;   // как у документов Базы знаний
  stage: 'capture' | 'edit';    // 'capture' — идёт съём потока мыслей, ещё не сгенерирована
  updatedLabel: string;
};
```

---

## 2. Поток создания (ключевая часть запроса)

```
[Новая заметка] → экран «Захват мысли» (stage='capture')
   ├─ большое поле ввода (текст или голос → распознавание речи в текст)
   ├─ кнопка микрофона: toggle записи, стрим текста в то же поле по мере распознавания
   └─ «Сгенерировать заметку» → вызов ИИ → title + Markdown-контент, stage → 'edit'
        ↓
[Редактор] (stage='edit') — открывается сразу на вкладке «Превью»
   ├─ вкладки Редактор / Превью (тот же компонент, что и раньше)
   ├─ правки от руки в текстовом поле
   └─ «Сохранить и индексировать» → POST заметки → RAG-сервис режет на чанки → обновить chunks/points
```

### Промпт для генерации черновика (реальный ИИ-вызов на бэкенде)

Отправлять сырой текст в LLM с инструкцией вида:
> Преобразуй неструктурированную голосовую/текстовую заметку в чистый Markdown:
> заголовок `#`, при необходимости `##`-разделы, списки для перечислений,
> таблицу для параметров/чисел, ничего не выдумывай сверх сказанного.

В прототипе это замокано детерминированной функцией (`transformRawText`) — просто
вытаскивает числа с единицами измерения в список «Параметры» и добавляет раздел
«Дальнейшие шаги». На проде — реальный запрос к LLM с этим промптом.

### Голосовой ввод

В прототипе — просто toggle иконки (🎙 → ⏺) без реального стрима. На проде:
Web Speech API (`SpeechRecognition`) или потоковая расшифровка через бэкенд —
результат дописывается в то же текстовое поле, что и обычный ввод.

## 3. Состояние экрана

```js
folder: 'all'|'work'|'ideas'|'personal'
tagFilter: string|null
query: ''
activeNoteId: string|null
mode: 'editor'|'preview'          // для конкретной активной заметки
rawText: ''                        // черновик потока мыслей (только в stage='capture')
voiceOn: false
generating: false                  // идёт ИИ-генерация черновика
saveState: 'idle'|'saving'|'saved' // статус "Сохранить и индексировать"
```

---

## 4. Markdown превью — рендерить как разметку, не как сырой HTML

Простой парсер построчно даёт массив блоков `{type, text}` (`h1`/`h2`/`h3`/`li`/`code`/`p`),
дальше рендерить их обычными компонентами (`<h1>`, список из `<li>`, `<pre><code>`, `<p>`).
**Не** вставлять как raw-HTML строку через `dangerouslySetInnerHTML` без санитайзера —
на проде через настоящий Markdown-парсер (remark/marked) с санитайзером (DOMPurify),
если контент может прийти извне.

Поддержать: `# `/`## `/`### ` заголовки, `- `/`* ` списки, ``` ``` ``` код-блоки,
`` `код` `` инлайн-код, `**жирный**`.

## 5. UI-детали

- **Список заметок**: закреплённые — отдельным блоком сверху (звёздочка, клик — toggle pin
  без открытия заметки, `stopPropagation`). Каждая карточка: заголовок, превью (первая строка
  контента без markdown-символов), теги (цветная точка + подпись), бейдж напоминания `⏰ дата`.
- **Теги**: фиксированная палитра из 5 цветов (важное/идея/todo/вопрос/референс), в шапке
  редактора — чипы с крестиком для удаления + «＋ тег» открывает палитру.
- **Напоминание**: `<input type="datetime-local">`, отображается в списке в формате `ДД.ММ ЧЧ:ММ`.
  Плюс отдельный флаг «📌 на потом» — простая заметка без конкретного времени.
- **Индекс-виджет в сайдбаре**: число заметок + суммарные точки в векторной БД —
  тот же паттерн, что в Базе знаний.

```css
.status-pill, .tag-chip, .mode-tab { white-space: nowrap; }   /* как и везде — не переносить однострочные лейблы */
```

---

## 6. Интеграция с Базой знаний / RAG

Заметка — такой же документ для векторного поиска, как файлы в Базе знаний:
на «Сохранить и индексировать» тело запроса то же, что при загрузке файла
(`title`, `content`, `owner`, `chunkSize`, `overlap` по умолчанию), только
`source_type: 'note'`. `chunks`/`points` обновляются по ответу индексатора
(в прототипе — грубая оценка `content.length / 220`).
